# Редактирование материалов

Учебный текст и листинги изменений находятся в `content/course.json`. Код неизменённой игровой основы — в `unity-project/Assets/Scripts`; нейтральный проект — в `starter-project`. Файлы `site/` создаёт существующий модуль `methodist.build`.

`assignment.pdf` содержит полное задание, файлы, методику и справочник исходного кода. `guide.pdf` — отдельный список 30 областей. Эти имена соответствуют импорту EatDoners. PDF используют A4, книжную ориентацию, поля 30/20/20/20 мм, локальный Golos Text 10,5/16 пт и сохранённый дизайн «блоки + маршрут». HTML использует экранный профиль того же дизайна.

`forms/template/Отчет о выполнении.docx` — сохранённая копия общего мастера BrainM. `scripts/build_report.py` адаптирует только разрешённые части копии: предметные поля, этапы и места рисунков. Остальные части пакета сохраняются побайтово. Поля SEQ/REF обновляются в Word до финальной проверки. Выдаётся только чистая `forms/Отчет о выполнении.docx`, которая копируется в `site/downloads/`.

Предпросмотр: `python -m methodist build .`. Итоговая сборка этого редакторского прохода: `methodist.build.build('.', release=True, evidence='docs/editorial-review.json')`. Профиль `unity-editorial` соответствует пользовательскому ограничению текущего поручения: текст, дизайн, исходные материалы и выдача; поле `unity_execution` равно false. Он не подтверждает запуск Unity, новые листинги или сборку приложения. Обычный режим технической приёмки сохраняет прежние проверки.

Перед выпуском проверяются исходный отпечаток, все 30 карточек, состав двух общих ZIP, сохранность текста PDF, отрисованные страницы и чистый отчёт. `python scripts/build.py --release` и `python scripts/check.py` проверяют подготовленный комплект. Pages публикует точную папку `site/`, не пересобирая её. После изменения текста, ресурсов или генератора требуется повторная проверка.

Нейтральная рабочая основа необходима, поскольку задание посвящено оформлению готовой механики. Отдельных стендов каждого варианта нет: профили всех правил уже включены; номер и индивидуальные условия выбираются по карточке. Оформленный тестовый проект имеет отдельную ссылку.

Текущие границы и доказательства хранятся в аудите УП ПМ.13 в BrainM. Новая проверка в редакторе Unity не выполнялась. Кадры из `Assets/Documentation` относятся к прежнему оформленному примеру; они не доказывают выполнение новых индивидуальных изменений.
